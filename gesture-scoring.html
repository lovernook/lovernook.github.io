01 / INPUT & ALGORITHM

鼠标连穴，如何变成可解释的评分？

评分不只要给出一个数字，还要回答：为什么失败、哪里画偏，以及不同帧率下是否仍然公平。

lovernook · 2026 年 9 月 28 日 · 基于《一笔江湖》项目复盘

先明确规则，再接鼠标输入

《一笔江湖》的施法是按顺序连接穴位。这里有两类不同问题：第一类是招式是否合法，例如漏穴、顺序错误、起止点不对；第二类是合法轨迹画得有多好。把二者混在一个加权分数里，会让一条顺序错误却外形相似的线获得高分。

因此评分分成“硬性检查”和“质量评分”。规则层是纯 C#，不依赖场景、动画或 Canvas；界面只负责采集与展示，同一套规则也可供服务端重算。

鼠标事件→ 画板局部坐标→ 采样与量化→ 合法性检查→ 质量评分→ 显示结果

输入坐标必须属于画板

输入来自屏幕，但路线定义在画板内。实现通过 ScreenPointToLocalPointInRectangle 和事件相机，把鼠标位置转为 RectTransform 局部坐标，再用矩形的最小值与宽高归一化。直接除以屏幕宽高，会在 Canvas 缩放、窗口变化或画板移动后产生偏差。

轨迹点用 0～10000 的整数表达，连续重复点会被移除。最多接受 512 点，越界、超量、点数不足与近乎零长度的笔画都有明确的失败路径。新一笔开始时立即清空上一次结果，避免“新轨迹尚未评分，却提交了旧成绩”。程序示范轨迹另有标记，不能作为正式手绘提交。

为什么不能只检查采样点是否在穴位里？

鼠标快速移动时，相邻两帧的采样点可能分别位于穴位左右两侧，线段已经穿过圆形区域，但两个端点都在圆外。仅做点与圆的包含检测会漏判。

当前实现检查线段与穴位圆的进入位置，把命中事件按线段参数 t 排序，再推进期望穴位索引。这样一段长线经过多个穴位时，仍能按穿越先后检查。紧邻的同穴抖动允许忽略；已经前进后返回旧穴、跳过中间穴位，则分别报告顺序或漏穴问题。起点和终点还要落在规定范围内。

等弧长采样，让评分尽量独立于画速

帧采样的密度会受到手速和帧率影响。如果直接平均原始点距离，停顿位置就会获得额外权重。实现先把玩家轨迹和模板各重采样为 64 个等弧长点，再计算三个质量项：

  • 形状：玩家点到模板折线与模板点到玩家折线的平均距离。双向计算能避免只画出模板的一小段就获得不合理的形状评价。
  • 对齐质量：两组等弧长点按序配对的平均距离，补充整体进度位置的差异。它与前面的“穴位顺序是否合法”是两层检查。
  • 长度：短轨迹长度除以长轨迹长度，抑制明显绕行。
// 公式摘录；距离基于归一化画板坐标
shape  = Clamp01(1 - (dp + dt) / 2 / 0.08)
order  = Clamp01(1 - pairedDistance / 0.12)
length = min(playerLength, targetLength)
         / max(playerLength, targetLength)
score  = Round(100 * (0.60*shape + 0.25*order + 0.15*length))

当前取整使用 AwayFromZero。0.08、0.12 与权重是当前实现中的参数，并不是普遍适用的“最佳手感”。将来调整时应同步客户端与服务端算法版本，并用固定轨迹回放比较新旧结果。

如何验证，如何继续优化？

项目已保存规则与 Unity 阶段回归记录；不能用“测试全绿”替代真人画线体验。对评分而言，最值得保留的回归输入包括：直线穿穴、同穴抖动、逆序、跳穴、零长度、越界、超量，以及形状相同但采样密度不同的轨迹。

下一步重点是收集真实手绘轨迹，检查不同分辨率与鼠标速度下的评分分布，再调整容差。目标不是把所有输入变成高分，而是让失败原因与玩家感受一致。
复盘问题：同一条折线，采样点翻倍，分数一定相同吗？

若只是在线段上补点、几何形状不变，等弧长重采样应使结果基本稳定；但量化、节点边界与总点数限制仍可能影响结果。可以构造两份轨迹做回归，分别观察合法性和三个质量项，不只比较总分。
